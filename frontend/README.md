# RAG v2 frontend

Next.js App Router, strict TypeScript, Tailwind v4, local shadcn/ui components and Lucide. Verified with Node 25.9.0 and npm 11.12.1; the native TypeScript unit-test runner requires Node 22.18 or newer. The backend remains the authority for every resource and administrator operation.

```sh
cd frontend
npm ci
# Start the separately configured v2 backend first (default 127.0.0.1:8000).
npm run dev
```

Open http://127.0.0.1:3000. Set the **server-only** `RAG_BACKEND_ORIGIN` if the backend uses a different origin. The backend's explicit `RAG_V2_ORIGINS` must include the browser origin. Production: `npm run build && npm start` (loopback). Do not expose a development server publicly.

The same-origin `/api/v2/*` gateway forwards only the application's session/CSRF cookies, validates write origins, applies a 32 MiB bounded body and a 120-second total deadline covering body reads and the upstream request, does not follow upstream redirects, and hides internal failures. The backend has stricter validation, upload limits, ownership and session enforcement. Auth uses HttpOnly server sessions; readable CSRF cookie is sent as `X-CSRF-Token`. No bearer or provider keys are stored in the browser. Local storage stores only the light/dark preference.

Screens cover login/setup, dashboard, chat, documents/upload/replacement/PDF previews, conversations/search/rename/delete, supported memories/deletion, settings, admin account controls and polling job activity/cancel/retry. Chat displays waiting feedback while the existing non-streaming backend completes; it does not simulate token streaming. PDF preview uses the authenticated gateway and original page fragment. Historical messages only display answer status/citations if the backend persists that metadata; new responses render both.

`lib/openapi.json` is the actual FastAPI schema, `lib/openapi.d.ts` is generated by pinned `openapi-typescript`, and `lib/api-types.ts` binds its v2 response types; `scripts/check-openapi.mjs` checks the used routes/methods against a running FastAPI OpenAPI document. Regenerate with `npx openapi-typescript lib/openapi.json -o lib/openapi.d.ts` after exporting the backend schema.

```sh
npm run typecheck
npm run lint
npm test
npm run build
npx playwright install chromium
npm run test:e2e
node scripts/check-openapi.mjs http://127.0.0.1:8000/api/v2/openapi.json
```

Browser tests named “UI contract fixtures” use intercepted deterministic API responses. They verify UI behavior, not the real database/OCR/provider/multi-process acceptance gate. Real backend/process integration is reported separately in the project release status. Tests have no provider keys or held-out inputs. shadcn/ui button/input/card source is locally adapted from its MIT registry: https://ui.shadcn.com/docs/components/button and https://ui.shadcn.com/docs/installation/manual. Next route-handler signatures follow https://nextjs.org/docs/app/api-reference/file-conventions/route.

The explicitly gated `tests/browser/live-core.spec.ts` requires a fresh identified scratch harness with a shared provider-call cap. It is excluded from ordinary provider-free verification. The genuine 11-call browser PASS and both preceding zero-provider harness FAILs are preserved in `evidence/`; the PASS summary explicitly records that its successful in-memory JSON attachment was not persisted, while actual rendered answers and SDK hash receipts were retained. No model output was reconstructed.
